Building the sensing hardware

MachineGuard is a machine-condition monitoring prototype built by SmolBugs for natHacks 2026. My main responsibility was the complete hardware side of the project. I assembled and integrated a Heltec WiFi LoRa 32 V3 (ESP32-S3), a Pololu MinIMU-9 v3 carrying the LSM303D three-axis accelerometer, an NTC thermistor circuit, and the board's OLED display into a sensor node that could run beside a power drill.

I wired the thermistor as a voltage divider for the ESP32's ADC and brought up the accelerometer over I²C. The display and IMU needed separate buses: the OLED uses the board's default I²C pins, while the accelerometer uses Wire1 on GPIO 2 and GPIO 4. Working through that board-specific constraint was key to getting stable readings from both peripherals at once.

Capturing vibration reliably

For useful vibration analysis, the gateway needed evenly spaced samples rather than occasional readings from the main loop. I implemented and debugged the ESP32 firmware to configure the LSM303D's FIFO, collect three-axis samples at about 1,600 Hz, and form 4,096-sample windows. The FIFO preserves the sensor's sampling cadence while the microcontroller handles other work; the firmware drops a window if acquisition fails instead of forwarding incomplete data as if it were valid.

I also worked through firmware bring-up and dependencies, sensor register communication, OLED status output, and the BLE link to the receiver. The board sends frequent status updates and encodes each vibration window as a start frame followed by compact binary data chunks. I worked on the packet format and receiver compatibility so the laptop could reconstruct full windows for analysis.

My engineering contribution

  • Owned the hardware build and integration for the competition prototype.
  • Integrated the ESP32-S3, LSM303D accelerometer, thermistor circuit, OLED, and their power and signal wiring.
  • Debugged dual I²C buses, sensor setup, ADC readings, and embedded firmware dependencies.
  • Built the acquisition path for FIFO-backed, three-axis vibration windows and BLE transmission.
  • Worked across the board-to-receiver boundary to keep binary BLE packets usable by the team's processing software.

Hardware as part of a complete system

The sensor node was one part of a team-built system. It sent data over Bluetooth LE to a Python receiver, where vibration windows could be reconstructed and analyzed before results flowed to the team's cloud dashboard. Building the device meant considering the full path from sensor timing and packet size through receiver expectations, rather than treating the microcontroller as a standalone demo.

The competition prototype demonstrated live sensing and data transfer. The broader predictive-maintenance pipeline and model were team efforts, and the prototype's temperature measurement still needed calibration before it could be treated as a reliable temperature value. This project gave me hands-on experience designing, wiring, bringing up, and integrating embedded hardware under a real competition deadline.
